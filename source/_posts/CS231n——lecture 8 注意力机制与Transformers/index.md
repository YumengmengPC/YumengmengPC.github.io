如果说 Lecture 7 让我们认识了处理序列的"经典方案"——RNN 和它的变体 LSTM，那 Lecture 8 要讲的，就是彻底改变整个深度学习版图的一个东西：**注意力机制和 Transformer**。

Transformer 已经是现在深度学习最常使用的架构。最初为机器翻译而生，如今横扫 NLP、计算机视觉、语音、多模态……遍地开花。

但注意力的故事不是从 Transformer 开始的。它诞生于 RNN 内部的一个朴素想法。

---

## RNN Seq2Seq 的瓶颈：为什么需要注意力？

回顾 Lecture 7 末尾的 Seq2Seq 架构：一个 RNN 作为编码器，按顺序消化输入序列，最终吐出一个固定长度的**上下文向量**总结整条输入序列的语义；然后另一个 RNN 作为解码器，每个时间步依赖这个上下文向量来生成输出序列的单词。

这个设计方案有一个致命伤。

**固定长度的上下文向量 = 通信瓶颈**。无论输入是三个单词的短句还是三百个单词的长段落，编码器都硬塞进一个固定大小的向量里。直觉上就很不对劲：一个固定维度的浮点数数组，凭什么能完整且准确地表示任意长度的信息？

修改思路很自然：处理输出序列时，给模型一个**回看输入序列**的机会。每输出一个新单词，都让解码器重新扫一遍整个输入序列——找出当前最该关注的部分，而不是死啃一个固定的上下文向量。

这就是注意力机制的动机。

---

## 注意力在 RNN 中的工作流程

从同样的编码器开始——它仍然读入输入序列，产生一系列隐藏状态 $h_1, h_2, \dots, h_T$。但解码器不再只看最后一个隐藏状态；它在每个时间步都会做以下三件事：

**第一步：计算对齐分数。** 拿解码器当前的隐藏状态 $s_{t-1}$，跟编码器的每一个隐藏状态 $h_i$ 做比较，算出一个个标量分数。分数高说明"当前位置和 $h_i$ 相关性大"，低则说明"不太相关"。

**第二步：Softmax 归一化。** 对齐分数只是一堆标量，可能大小悬殊。用 softmax 把它们压成概率分布——每个分值变成 $[0,1]$ 之间的权重，且所有权重加起来等于 1。

说白了你现在拥有的是输入 token 的一个概率分布——网络在不同输入位置上的"关注度预算"。

**第三步：加权线性组合。** 用这些注意力权重，对编码器的隐藏状态做一个加权求和，得到当前时间步专属的上下文向量 $c_t$。

然后，把上下文向量 $c_t$ 与上一个输出 token 的嵌入拼接，一起喂给解码器 RNN，产生下一个隐藏状态 $s_t$，再从 $s_t$ 预测输出 token。

举个例子：翻译 "We see the blue sky" → "Vediamo il cielo blu"，当解码器要输出 "Vediamo"（"我们看到"）时，注意力机制自然地对 "we" 和 "see" 这两个位置给出高分，而不是后面的 "blue" 或 "sky"。

**关键点**：注意力机制不需要你告诉它"应该关注哪里"。对齐函数 $f_a$ 本身是可学习的（通常是一个小型前馈网络或点积运算），编码器和解码器的参数一起通过梯度下降端到端训练。对齐模式是网络自己"悟"出来的。

---

## 每个时间步都要重新计算

输出一个单词之后，解码过程重复：第二个时间步重新计算一遍对齐分数 → softmax → 加权和，得出新的上下文向量 $c_1$，连同之前的解码器状态 $s_1$ 和下一个输出 token，产生 $s_2$，再输出下一个单词。

直觉：解码器在每个时间步都有机会**重新总结输入序列**，动态生成专属于当前输出位置的上下文向量。这是一个"在需要时回头看一眼"的机制。

这种设计的副产品也很有价值——你可以通过观察注意力权重的分布来理解模型的"思考过程"。典型的序列到序列翻译任务中，注意力矩阵往往呈对角线分布（一一对应的单词对齐），也可能出现交叉对齐（语序不一致时的重排）。这种可视化本身就成了模型可解释性分析的有力工具。

![注意力对齐矩阵：对角线模式显示输入输出一一对应](/images/attention_weights_visualization.png)

## 从 RNN 特供到独立算子：抽象注意力机制

到目前为止，注意力是绑定在 RNN Seq2Seq 上的增强组件。但能不能把它抽象出来，变成一个通用的、独立于 RNN 的运算？

答案是可以。而这种抽象就是后来一切 Transformer 变体的共同基础。

### QKV：查询、键、值

把注意力看成一个对向量集的运算，需要三个角色：

| 角色 | 全称 | 在做什么 |
|------|------|---------|
| **Q**（Query） | 查询向量 | "我现在想要什么信息？" |
| **K**（Key） | 键向量 | "我能提供什么样的匹配信息？" |
| **V**（Value） | 值向量 | "如果匹配了，你该拿到什么内容？" |

类比数据库检索：你有一个查询 Q，每个数据项有一个键 K 用于匹配、一个值 V 作为检索内容。Q 跟所有 K 比一下相似度 → softmax 得到权重 → 用权重把 V 组合起来 → 输出。

![Scaled Dot-Product Attention](/images/arxiv_attention_scaled_dot.png)

### K 和 V 从哪里来？

原始 RNN 注意力中，K 和 V 就是编码器的隐藏状态——数据向量直接既当 K 又当 V。在抽象注意力层中，我们让网络自己学习两个投影矩阵：把每个数据向量 $x_i$（维度 $D_X$）分别投影成键向量 $k_i$ 和值向量 $v_i$。

$$k_i = x_i W_K, \quad v_i = x_i W_V$$

其中 $W_K$ 把 $D_X$ 映射到 $D_Q$（跟查询同维度以便点积比较），$W_V$ 把 $D_X$ 映射到 $D_V$（输出向量的维度）。

**直觉**：把"想要匹配的条件"（Key）和"匹配后应该获得的答案"（Value）分开，让网络自己决定一个数据向量的什么部分用于匹配、什么部分作为内容被取走。

### 交叉注意力层的完整定义

至此，我们得到了一个独立的、可堆叠的神经网络层——**交叉注意力层**：

1. 输入：一组查询向量 Q 和一组数据向量 X
2. 通过 $W_K, W_V$ 把 X 投影成 K、V
3. 计算 Q 和 K 的相似度矩阵：$S = QK^T$
4. 除以 $\sqrt{d}$ 做缩放（防止点积值过大把 softmax 推到饱和区）
5. softmax 归一化：$A = \text{softmax}(S / \sqrt{d})$
6. 输出：$O = A \cdot V$

写成一行：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d}}\right) V$$

两个可学习的参数：$W_K$ 和 $W_V$。输入两组向量序列，输出一组向量序列——这就是一个完整的神经网络层。

**为什么除以 $\sqrt{d}$？** 如果不缩放，当维度 $d$ 变大时，点积 $q \cdot k$ 的数量级也会变大，softmax 的输入值出现较大方差，导致 softmax 输出逼近 one-hot 分布——梯度趋近于零。除以 $\sqrt{d}$ 把方差控制在大约 1 的水平，保持梯度健康。

## 自注意力：自己关注自己

交叉注意力有两个输入源（Q 来自一方，K/V 来自另一方）。**自注意力**则只有一个输入序列——Q、K、V 全部来自同一组向量。

输入是一组向量 X。用三个可学习的投影矩阵 $W_Q, W_K, W_V$ 把同一个 X 分别映射为 Q、K、V：

$$Q = XW_Q, \quad K = XW_K, \quad V = XW_V$$

![自注意力：输入向量投影为 Q、K、V 三组](/images/attention_layer_QKV.png)

后续计算完全一样：$QK^T$ → scale → softmax → 乘以 V。

![自注意力的输出 = 对各位置 value 的加权和](/images/self_attention_overview.png)

现在有三个可学习的矩阵了（$W_Q, W_K, W_V$）。实现上可以把 QKV 投影**融合成一次矩阵乘法**——把三个权重矩阵拼成一个大的 $W_{QKV}$，一次 matmul 直接产出拼接好的 Q、K、V 张量，再按维度切开——GPU 上更高效。

### 顺序不变性（Permutation Equivariance）

纯自注意力有一个有趣的特性：**改变输入序列的顺序，输出也以相同规则改变顺序，但值不变。**

为什么？因为 softmax 不关心位置——它对一行里的元素做归一化，打乱行的顺序不会改变每个内部的值。所以纯粹的自注意力层是"置换等变"的。

这意味着：自注意力**天然感知不到绝对位置**。如果不做任何处理，"猫追狗"和"狗追猫"在自注意力看来没有区别（只是 K/V 的顺序变了，但加权求和的值是一样的）。

解决方法：在输入向量中注入**位置编码**（positional encoding）。可以在输入上加正弦位置编码，也可以用可学习的位置嵌入——不管哪种方式，目标都是给每个向量打上一个"我是第几个"的标签。

### 掩码自注意力

在语言生成（自回归解码）场景中，当前位置不应该偷看未来的 token。怎么办？

在计算 $QK^T$ 后、做 softmax 之前，把未来位置的分值设为 $-\infty$。这样 softmax 之后，那些位置的权重就是 0——模型只能看到当前及之前的 token，保持因果性。

## 多头注意力

单头自注意力只能学习一种"关注模式"。但实际语言中，同一个词可能需要同时关注语法搭配、指代消解、语义关联……一种关注模式不够。

**多头注意力**的做法简单粗暴：并行运行 $h$ 个独立的注意力头，每个头有自己的 $W_Q^{(i)}, W_K^{(i)}, W_V^{(i)}$。

![多头注意力：多组独立 QKV 投影并行计算](/images/multihead_overview.png)

每个头独立算一遍注意力，然后把各头的输出拼接起来，再经过一个线性投影融合。

![Multi-Head Attention](/images/arxiv_attention_multihead.png)

$$\text{MultiHead}(X) = \text{Concat}(\text{head}_1, \dots, \text{head}_h) \cdot W_O$$

![多头注意力：各头输出拼接后线性投影](/images/multihead_concat.png)

不同头之间架构完全一样、计算完全一样，**只有权重不一样**。不同的随机初始化导致各头学会关注不同的模式——有的头可能专门捕捉位置关系，有的头捕捉语义相似性，有的关注主谓搭配……

在实践中，通常把单头维度缩小（比如总维度 512 分给 8 个头，每头只算 64 维的 QKV），然后各头并行计算。整体计算量差不多，但表达能力大幅提升。**多头注意力是 Transformer 在实际工程中唯一可用的自注意力形态**——基本上不会有人只用单头。

## 三种序列处理原语的对比

在 Transformer 出现之前，处理序列主要靠 RNN 和卷积。自注意力提供了第三种路径。三者各有优劣：

| 原语 | 并行性 | 感受野 | 核心瓶颈 |
|------|--------|--------|----------|
| **RNN** | 差——时间步之间串行依赖 | 随深度线性增长 | 梯度消失/爆炸，训练慢 |
| **卷积** | 好——各位置可并行 | 需要深度堆叠或大核才能全局 | 捕捉长距离依赖昂贵 |
| **自注意力** | 很好——本质是矩阵乘法 | **单层即可全局** | 复杂度 $O(n^2)$，长序列吃内存 |

RNN 的痛点是并行——每个时间步依赖上一步的结果，整条序列必须串行处理。卷积解决了并行但痛在感受野——要看到远处的像素得堆很多层。自注意力一次性解决了并行和感受野这两个问题，代价是 $O(n^2)$ 的计算和内存。

对于"长度不超过几千"的序列（大部分 NLP 场景），$O(n^2)$ 完全可接受。但对于长文档、高分辨率图像，这确实是个瓶颈——这也是后来各种高效注意力变体（FlashAttention、Linformer、sparse attention 等）涌现的原因。

## Transformer 架构

2017 年，《Attention Is All You Need》这篇论文把自注意力推上了王座。Transformer 的核心组件——Transformer Block——由以下层叠成：

1. **多头自注意力**（全局两两交互）
2. **残差连接 + LayerNorm**（稳定梯度）
3. **逐位置前馈网络 / MLP**（每个位置独立做非线性变换）
4. **残差连接 + LayerNorm**

![Transformer 完整架构](/images/arxiv_transformer_arch.png)

![Transformer Block 内部的残差连接与 LayerNorm](/images/transformer_block_detail.png)

写成伪代码：

```python
def transformer_block(x):
    # 1. 多头自注意力 + 残差 + 归一化
    attn_out = multi_head_self_attention(x)
    x = layer_norm(x + attn_out)
    
    # 2. 前馈网络 + 残差 + 归一化
    ff_out = mlp(x)   # 两层全连接，中间加激活函数
    x = layer_norm(x + ff_out)
    
    return x
```

设计思路其实很有意思：**把全局交互和局部处理拆分开来**。

- 自注意力层负责"每两个位置之间要不要交换信息"——它让每个 token 都能看到所有其他 token
- MLP 层负责"每个位置内部怎么加工信息"——它对每个位置单独做非线性变换，各位置之间不交流

这种分工让 Transformer 既拥有了自注意力的全局视野，又保留了 MLP 的表达能力。残差连接和 LayerNorm 则是让训练在深层时保持稳定的工程技巧。

堆叠 N 个这样的 block，就得到了完整的 Transformer。从几层的小模型到几百层的巨型模型，从百万参数到万亿参数，这个架构展现了出奇的扩展性——目前为止的天花板，基本上是硬件的算力和内存，而不是架构本身。

## ViT：把 Transformer 用到图像上

Transformer 最初为文本设计——输入是一个 token 序列，天然的集合结构。图像怎么办？

Vision Transformer（ViT）的做法直白到有点粗暴：把一张图片**切成一个个固定大小的 patch**（比如 $16 \times 16$ 的方格），把每个 patch 拉直、通过一个线性层投影成一个向量——这个向量就是一个"视觉 token"。加上位置编码，整组向量喂进标准 Transformer，完事。

对于图像分类任务，在输入序列前面追加一个额外的可学习 token（通常叫 `[CLS]` token），Transformer 处理完后，把这个 `[CLS]` 对应的输出向量拿出来，过一层线性分类器，得到分类分数。也可以对全部位置的输出做池化，再连分类头。

ViT 的核心洞察：**图片天然可以看成一个 patch 的集合**——就像句子是一个词的集合。只要把视觉元素 token 化，剩下的事 Transformer 完全可以照搬。

自 ViT 之后，计算机视觉领域迅速从"万物皆 CNN"过渡到了"Transformer 处处开花"。分割、检测、生成……后面会细讲。
