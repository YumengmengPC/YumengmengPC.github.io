## 从专用模型到基础模型

训练模型的传统思路是"一个任务一个模型"——数据域 1 训练模型 1，数据域 2 训练模型 2。换一个任务就得重新收集数据、重新训练。

**基础模型 (Foundation Model)** 的思路彻底翻了这个范式：用海量多样化的数据预训练**一个**大模型，让这个模型充当后续各种任务的"地基"。接下来不管是分类、检测、问答还是生成，都在这个地基上微调、few-shot、甚至 zero-shot 就能干活，不需要从头训起。

![基础模型的概念](/images/lec16_foundation_model.webp)

GPT 是这个思路最好的例子——用互联网上抓下来的 Common Crawl 语料做预训练，然后同一个模型可以应对数学推理、符号推理、翻译、问答等一系列任务。它的预训练目标只是"预测下一个 token"，但学到的表示足够通用，能被迁移到完全不同的下游场景。

这节课把现有的基础模型分成了几大类：

* **语言模型**：ELMo、BERT、GPT、T5——纯文本世界的产物，不在本节课范围内
* **分类模型**：CLIP、CoCa——把图像和文本对齐到同一个嵌入空间
* **LM + Vision**：LLaVA、Flamingo、GPT-4V、Gemini、Molmo——让语言模型能"看见"图像
* **其他**：Segment Anything (SAM)、Whisper、DALL·E、Stable Diffusion、Imagen——各自在分割、语音、生成领域充当基础模型
* **链接 (Chaining)**：LM + CLIP、Visual Programming——不训新模型，把现成的串起来用

基础模型通常有几个共同特征：对多种下游任务有较好的鲁棒性、参数量大、训练数据规模大、使用自监督预训练目标。它们放弃了对单一任务的极致优化，换来跨任务的泛化能力。

## CLIP：对比语言-图像预训练

### 从 SimCLR 到多模态

上学期讲自监督学习时介绍了 SimCLR：用对比学习让同一张图片的两个增强视图在表示空间中靠近，不同图片的视图远离。核心想法是"不依赖标签，靠数据本身的变换不变性来学表征"。

这节课问了一个很自然的问题：**能不能把文本也拉进这个表示空间？**

![SimCLR 到 CLIP 的演化](/images/lec16_clip_arch.webp)

SimCLR 只有图像编码器，两张图经过同一个编码器后去算对比损失。CLIP 的做法是再加一个文本编码器，让"一只毛茸茸的猫"这句话的嵌入靠近猫的图片嵌入，让"金毛是我最喜欢的狗"靠近金毛的图片嵌入。训练目标和 SimCLR 一样是对比学习，但正样本对变成了 (图像, 对应文本描述)，负样本是同一批次中所有其他文本。

CLIP 的对称对比损失（InfoNCE）同时往两个方向计算交叉熵：

$$\mathcal{L}_{\text{CLIP}} = \frac{1}{2}\left(\mathcal{L}_{\text{image}\to\text{text}} + \mathcal{L}_{\text{text}\to\text{image}}\right)$$

对于批次中的 N 个图文对，image→text 方向把每个图像当查询，在 N 个文本候选中找正确的那个（对角线）；text→image 方向反过来，每个文本在 N 个图像中找匹配。两个方向的损失取平均。温度参数 $\tau$ 控制 softmax 的锐度——$\tau$ 越小，模型对相似度差异越敏感。

训练数据从哪里来？互联网上天然有大量图文对。CLIP 的训练集就是爬了 4 亿条网页上的图片和它们的附带文本（alt-text、标题、上下文描述），没有人工标注。这比任何有监督的图像分类数据集都大几个数量级。

### Zero-shot 分类：用文本编码器当分类器

CLIP 最有意思的用法是 zero-shot 分类。思路本身很巧妙：

1. 把数据集中所有类别名称编码成文本向量。不是只用一个单词，而是用短语模板——比如 `"a photo of a dog"`、`"a drawing of a dog"`、`"a blurry photo of a dog"` 等——每个类别生成一批文本向量后取平均，得到这个类的**原型向量**
2. 给一张新图像，用图像编码器提取特征
3. 算图像向量和所有类原型向量的余弦相似度，最近的那个就是预测类别

![Zero-shot 分类流程](/images/lec16_zero_shot.webp)

整个过程本质上是一个 1-近邻分类器：所有类的文本嵌入是"中心"，来了新图像找最近的中心。Prompt 工程在这里很关键——用单个单词（"dog"）做向量效果远不如用短语，因为 CLIP 的训练数据就是短语形式的，模型没见过单词语境。多个模板取平均（prompt ensembling）能进一步减少单个模板的偏差。

CLIP 预训练的两步流程：

* **传统路线（SimCLR 等）**：预训练编码器 → 下游任务需要接线性分类器 → 需要该任务的标注数据来训练这个分类器
* **CLIP zero-shot 路线**：预训练编码器 → 直接开箱即用，不需要任何下游标注数据。分类器不是训出来的，是"写"出来的——文本描述就是分类器

为什么 CLIP 的 zero-shot 效果这么好？几个原因：

首先，**规模**。CLIP 用了 ViT 架构（最早版本用 ResNet，后来 ViT 版本更好），3 亿+ 参数，4 亿图文对训练数据。这个数据规模远超任何监督数据集，模型见过的视觉概念多样性天然更广。

其次，**互联网数据的多样性**远超人工标注数据集。网上不仅有照片，还有素描、图表、卡通、3D 渲染，文本描述包含颜色、形状、空间关系、材质等结构化信息。这些东西 ImageNet 标签里都没有。

<｜｜DSML｜｜parameter name="new_string" string="true">open-vocabulary 的特性让 CLIP 能处理任意类别——想加一个新类，写一段描述就行，不需要重新训练。这对于标签空间动态变化的场景非常有用。

还有一个让人惊讶的结果：**CLIP zero-shot 在 ImageNet 上的分类准确率，与全监督训练的 ResNet-101 持平**。要知道 ResNet-101 是用 128 万张人工标注的 ImageNet 图片训练出来的，CLIP 完全没有见过 ImageNet 的标签——它只是碰巧在 4 亿图文对中见过这些类别的图片和文字描述。参数规模上，CLIP ViT-L/14 有 3.07 亿参数（ResNet-101 只有 4450 万），这个差距在后面的基础模型中还会被进一步拉大。

更值得关注的是 CLIP 的**分布外泛化能力**。在 ImageNet 上训练的 ResNet-101 一旦遇到 ObjectNet（同样 1000 类但拍摄视角完全不同——杯子从正上方拍、椅子从底部仰拍），准确率直接跳水。CLIP zero-shot 在 ObjectNet 上的表现远超监督模型。不仅真实照片变视角不虚，换成素描、卡通、对抗样本，CLIP 照样稳。原因还是那个——它在互联网上见过了太多不同形态的"猫"：照片、插画、涂鸦、3D 渲染。

### CLIP 的局限

CLIP 不是没有短板。

**对批次大小极度敏感**。对比学习的负样本来自同一批次，批次太小就没有足够多的"难负样本"来推动模型学习细粒度概念。实验表明，batch size 为 4 时模型只能学到"动物"这个层级，batch size 到 100 能区分"狗"，到 32000 才能区分"威尔士柯基"。但这种靠增大 batch 来撞到难负样本的方式有天花板——即使 batch size 到 32K，你也不太可能恰好同时遇到"草地上的杯子"和"杯子里的草"这种需要精细区分的配对。

**组合性推理失败**。CLIP 分不清"草地上的杯子"和"杯子里的草"——两个概念调换位置后，模型给出的相似度几乎一样。Winoground、CREPE、ARO 等 benchmark 专门测这种属性绑定能力，CLIP 表现接近随机。这暴露了对比学习的一个深层问题：全局余弦相似度把整个图像压缩成一个向量，丢失了局部结构和属性绑定的信息。

**Hard negative 训练是双刃剑**。刻意构造"马吃草 vs 草吃马"这种迷惑性负样本可以提升 CLIP 的组合性，但也会误伤正常的正样本——"一只黑猫和一只棕狗" vs "一只棕猫和一只黑狗"都是合理的描述，但如果训练时把后者当负样本，模型就被教错了。

**图像级别的描述不足以提供充分监督**。互联网文本通常是主观的、随意的，缺少空间位置、材质、数量等信息。CLIP 学到的更多是"什么东西出现了"而不是"东西之间是什么关系"。比如一张客厅照片的 alt-text 只写了"living room"——模型不会知道里面有植物、有沙发。可以用带边界框的区域描述来补充训练，但要靠对比学习从图像级别的 caption 里挤出空间理解，上限是有限的。

**你没法在 50 亿的数据集里知道一切**。不管数据集多大，总有些概念、属性、关系是 CLIP 没见过的。所以有意识地收集和筛选数据——而不是无脑爬更多网页——才是提升模型上限的关键。这一点在后面的 Molmo 部分还会再次出现。

CLIP 还有一个微妙之处：**linear probe 和 zero-shot 的性能差异**。在大多数数据集上，用 CLIP 提取特征再接一个线性分类器（linear probe），效果比 zero-shot 好。这很好理解——linear probe 有该任务的标注数据，zero-shot 全靠文本"猜"。但在某些数据分布差异极大的场景下，zero-shot 反而更强，因为 linear probe 容易过拟合到训练数据的偏差上，而 zero-shot 的文本描述不受标注分布的限制。

## CoCa：对比 + 描述生成

CLIP 只做对比——判断图文是否匹配，但不需要模型真正"理解"图片里有什么。CoCa（Contrastive Captioners）在 CLIP 的基础上加了一个**描述生成解码器**：除了对比损失，模型还要自回归地生成图片的完整文字描述。

![CoCa 架构：在 CLIP 基础上加入描述解码器](/images/lec16_coca.webp)

CoCa 的架构和 CLIP 一样是双编码器，但从图像编码器的输出额外接了一个解码器，通过交叉注意力 (cross-attention) 来关注图像特征，自回归地生成 caption。这个解码器不仅仅是在做"图生文"，它反向迫使图像编码器学到更丰富的特征——要生成准确的描述，编码器必须捕捉颜色、形状、空间位置、物体之间的关系。对比损失告诉模型"这两者是不是一伙的"，描述损失告诉模型"图里到底有什么、它们之间是什么关系"。两个目标互补。

结果上，CoCa 在 ImageNet 上达到了 91.0% 的 top-1 准确率，超过了所有传统的监督模型。这证明了"更强的学习目标"比"更多的标签"更管用。

CoCa 之后，分类基础模型这条线上还有 SigLIP（用 sigmoid 损失替代 softmax，去掉了对大批次的依赖）等改进，但核心思想是相同的：用图文对齐来学通用视觉表示。

## 多模态语言模型：让 LLM 看见图像

CLIP 和 CoCa 解决的是"对齐"问题——把图像和文本映射到同一个空间。但如果想让模型看图回答问题、看图写描述、甚至看图做推理，光有对齐不够，需要让语言模型**在生成文本时能够参考图像内容**。

### 为什么选 LLM 做底座

LLM 有一个很关键的性质：自回归的 next-token-prediction 框架天然支持多种任务。同一个模型可以同时做数学推理、情感分析、符号推理——只需要改变输入的 prompt。那如果在输入中同时给一些"图像 token"，是不是就能让 LLM 看图说话了？

这个想法可以追溯到 2019 年的 ViLBERT——当时就已经尝试了在视觉-语言任务中使用 Transformer。但 ViLBERT 的问题是每个任务都需要单独微调，不能像今天的模型一样泛化。LLaVA 之所以成为里程碑，是因为它第一次把预训练视觉编码器和预训练 LLM 拼在一起，通过一个简单的投影层连接，用指令微调的数据训出了一个能对话的视觉-语言模型。

### LLaVA：最简单的配方

LLaVA 的架构非常直接，三个组件：

1. **视觉编码器**：预训练的 CLIP ViT。图像被切成 patch，每个 patch 产生一个 token。关键细节——LLaVA 用的不是 CLIP ViT 最后一层的 CLS token（那个 token 只被对比学习目标监督，空间信息已经丢失），而是**倒数第二层的 patch tokens**。这些中间层的 token 保留了更多的局部和空间信息，更适合作为视觉特征喂给 LLM
2. **投影层**：一个简单的线性层，把 ViT 输出的 patch token 维度映射到 LLM 的 embedding 维度。这个投影层是**需要训练**的——它是两个预训练模型之间的"翻译器"
3. **LLM**：Vicuna / LLaMA 等自回归语言模型。图像 token 和文本 token 拼接在一起输入，LLM 根据视觉+文本的上下文自回归地生成回答

![LLaVA 整体架构](/images/lec16_llava_arch.webp)

LLaVA 的训练分成两个阶段。第一阶段只训练投影层，视觉编码器和 LLM 都冻结——这一步的目的是让图像 token 学会"说 LLM 能听懂的话"。第二阶段用图像-指令-回答三元组做指令微调，可以同时微调 LLM 参数。这个两阶段策略保证模型既学会了对齐，又学会了跟随指令。

### Flamingo：门控交叉注意力

Flamingo 走了另一条路。LLaVA 是把图像 token 塞进 LLM 的输入序列，Flamingo 则是在 LLM **每一层**都插入可以关注图像特征的模块。

Flamingo 有两个需要训练的部分（其余全部冻结）：

**Perceiver Resampler**。视觉编码器输出的 token 数量取决于图像大小，变长的。Perceiver Resampler 是一个小的 Transformer，用固定数量的可学习 query 去关注变长的视觉 token，输出**固定长度**的视觉表示。这样不管图像多大，喂给 LLM 的视觉 token 数量始终不变。

![Flamingo 完整架构](/images/lec16_flamingo_arch.webp)

**Gated XATTN-DENSE 层**。在 LLM 每个冻结的 Transformer block 之间插入两个小模块——交叉注意力 (cross-attention，用文本 token 去查视觉 token) 和一个 FFW 层。每个模块前面有一个**可学习的门控参数** $\alpha$，初始化为 0。前向过程是：

$$y = y + \tanh(\alpha_{\mathrm{xattn}}) \cdot \operatorname{CrossAttn}(q=y, kv=\mathrm{visual\_tokens})$$

$$y = y + \tanh(\alpha_{\mathrm{dense}}) \cdot \operatorname{FFW}(y)$$

$\tanh(0) = 0$，所以训练刚开始时门是关闭的——视觉信息完全没有流入，模型行为等同于原始的冻结 LLM。训练过程中 $\alpha$ 逐渐增大，门慢慢打开，模型开始利用视觉信息。这个设计很聪明：它保护了 LLM 原有的语言能力，让视觉信息成为"增强"而不是"干扰"。

![Flamingo 门控交叉注意力](/images/lec16_flamingo_gated.webp)

**训练方式：交错图文序列**。Flamingo 把一堆 (图像, 描述) 对拼接成一个长序列——`<image> caption1 <eos> <image> caption2 <eos> ...`。但这里有个关键设计：训练时使用**掩码注意力 (masked attention)**，确保每个文本 token 只能关注到它对应的那张图像，不能跨图像偷看。如果不加这个掩码，模型就可能用前一张图的视觉信息来生成当前图的描述，学到的就不是"看图说话"而是"偷看答案"。

掩码注意力的另一个好处是让 Flamingo 在推理时天然支持**上下文学习 (in-context learning)**。给模型看几个 (图像, 类别) 示例对，再给一张新图像，模型就能参考上下文中的示例来做 classification——全程不需要微调任何参数。Flamingo 是第一个展示多模态 in-context learning 能力的模型。

### 开源 VLM 的困境

在 Flamingo 之后，GPT-4V、Gemini、Claude 3.5 等闭源模型快速崛起，在多模态 benchmark 上形成了明显的性能优势。课程幻灯片展示了一个很关键的对比：2024 年的 VLM 可以分为四个层级——

* **API Only**：GPT-4V、Gemini——只能通过 API 调用，权重、数据、代码全不公开
* **Open Weights**：LLaVA、QwenVL——权重开源，但训练数据和代码不完整
* **Distilled Open**：多数"开源"VLM 实际上是从 GPT-4V 蒸馏出来的——用 GPT-4V 的输出来训练自己的模型。这导致它们永远无法超越 GPT-4V，而且严格来说在使用条款上有灰色地带
* **Completely Open**：权重建模 + 数据 + 代码 + 评测全开源——这是 Molmo 的目标

"Never bet against open-source software"——幻灯片上专门引用了这句话。Molmo 的出发点就是：不靠蒸馏 GPT，不从 API 模型偷师，用完全开源的数据和代码训出一个能跟闭源模型正面竞争的东西。

Molmo 是 Allen AI 在 2024 年 9 月发布的完全开源 VLM。它的架构没什么特别的——CLIP patches → 简单 connector → LLM——但它的性能在人类评测中排名第二，仅次于 GPT-4o，超过了 Gemini 1.5 Pro 和 Claude 3.5 Sonnet。7B 的版本甚至超过了 LLaVA OneVision 72B 和 GPT-4V。

Molmo 之所以能"以小博大"，核心秘密在数据。

LLaMA 3.1V 用了 60 亿图文对做预训练——都是网上爬的。Molmo 用的**PixMo 数据集只有 70 万图文对**，少了近 100 倍，但质量远高于网上随便爬的内容。互联网图文数据是"偶然的"——「粉色、日本、美学图片」「喜欢这张冬天的图」，主观、松散、缺少视觉信息。PixMo 的标注是"故意的"——标注员对着图片用**说话**而不是打字的方式来描述（人不喜欢打长文本但喜欢说话），每张图讲 60-90 秒，描述中包含位置、材质、形状、空间关系、数量等信息。

标注流程并不只是"随便讲讲"。标注员被引导回答一系列具体问题：你第一眼看到的是什么？图中有哪些物体、分别有几个？文字写的是什么？每个物体的位置关系？背景里有什么细节？图像的风格是什么？这种结构化引导确保了描述覆盖了视觉理解的多个维度。语音描述再通过 ASR 自动转成文本，用来做预训练。

![Molmo 数据质量对比](/images/lec16_molmo_pointing.webp)

Molmo 的另一个创新是**指向机制 (pointing)**。输出不只是文字，还包含像素坐标——`<point x="63.5" y="44.5" alt="Mt Rainier">雷尼尔山</point>`。这让模型可以把语言描述直接锚定到图像的特定位置上，实现真正的 grounded reasoning。幻灯片上列举了指向的几种典型场景：**指着数 (pointing to count)**——数物体时明确指出每个物体的位置；**指着定位 (pointing to ground)**——描述一个物体时给出它的精确坐标。从感知到行动的链条在这里开始闭合：模型不仅知道"有三只猫"，还能指出每只猫在哪里。Molmo + SAM 2 的链接顺理成章——Molmo 指出物体位置，SAM 2 根据这些点做分割。

Molmo 的故事说明了一件事：在多模态领域，数据的**意图性**比**量级**更重要。700K 高质量的、有意标注的图文对，效果可以超过 6B 随便爬来的对。

---

## SAM：可提示的分割基础模型

前面讲的模型都是"图→文"或"图文对齐"。SAM (Segment Anything Model) 解决的是另一个问题：**分割**。

传统的分割模型（如 Mask R-CNN）只能分割训练数据中定义好的类别（COCO 的 80 类），换个新类别就得重新标注、重新训练。**分割的基础模型**应该什么样？应该能对用户关心的**任意**物体输出分割掩码——不管这个物体的类别在不在训练集中，只要用户在图像中指出来就行。

### 架构：图像 + Prompt → 掩码

SAM 把分割重新定义为**可提示 (promptable)** 的接口，三个组件：

1. **图像编码器**：重的 ViT，每张图只跑一次，输出密集的视觉特征
2. **Prompt 编码器**：轻量级，接收用户的各种提示——点 (point)、框 (box)、文字、甚至粗糙的掩码——把它们编码成统一的表示
3. **掩码解码器**：轻量级，根据图像特征 + prompt 表示输出分割掩码

![SAM 架构](/images/lec16_sam_arch.webp)

三个组件各司其职：图像编码器负责"理解图像内容"，prompt 编码器负责"理解用户到底想切什么"，掩码解码器负责"根据前两者生成精确的边界"。重的编码器只跑一次，轻的解码器可以反复跑——用户交互式地加 prompt、改 prompt，模型都能实时响应。

### 处理歧义：输出多个掩码

假设用户点了一下图片中的猫。用户到底想切出"猫的整体轮廓"、"猫的头"、还是"猫的耳朵"？一个点可能有多个合理的分割答案，没有唯一正确。

SAM 的做法是**同时输出多个不同粒度的掩码**，让用户自己选最合适的。训练时，对于每个 prompt，SAM 生成多个掩码，只选和 ground truth 最接近的那个计算损失——其他（可能也合理的）掩码不被惩罚。这个"不惩罚模棱两可"的设计是 SAM 能泛化的关键。

### 数据引擎：人机循环迭代

SAM 的成功很大程度上来自它的数据流水线。过程是这样的：

1. 人类标注员先手动标一批种子数据
2. 用种子数据训练 SAM，用训好的模型去标注更多图片
3. 标注员检查并修正模型的输出（比从零标注快得多）
4. 把修正后的数据加进训练集，重新训练，模型变得更好
5. 重复。每次迭代模型的输出质量更高，标注员修正的工作量更少，标注吞吐量指数增长

这个循环让 SAM 最终拥有了超过 10 亿个掩码的训练数据（SA-1B 数据集），覆盖了之前所有分割数据集都没见过的类别和场景。

和 CLIP 一样，SAM 也展示了令人印象深刻的 zero-shot 泛化。在完全没见过的图像域上——医学影像、卫星图、水下照片——SAM 不做任何微调就能输出质量不错的分割。当然不是完美的，但考虑到它从来没在这些域上训练过，表现已经远远超出了传统分割模型的能力边界。这进一步验证了基础模型的核心理念：**用足够大的数据和足够通用的接口，模型学到的是"什么是物体"而不是"COCO 的 80 个类别长什么样"**。

## 链接基础模型：CuPL 与 VisProg

在把所有能力塞进一个模型之前，还有一条路：**把已有的基础模型串起来用**。一个模型的输出给另一个模型做输入，不用训练新模型，靠组合获得新能力。

### CuPL：让 LLM 帮 CLIP 写 prompt

CLIP 做 zero-shot 分类时需要人工写 prompt 模板。但如果 CLIP 面对的是一个从来没见过训练数据的罕见类别——比如"鸭嘴兽"——怎么写 prompt？人都不一定知道鸭嘴兽长什么样。

CuPL 的思路：**让 LLM 生成描述，CLIP 用描述做分类**。对于一个新类别，先问 GPT："鸭嘴兽长什么样？"GPT 返回一段详细描述（"鸭嘴兽是一种半水生哺乳动物，有扁平的像鸭子一样的喙、棕色的毛皮、扁平的尾巴..."），然后把这段描述作为文本查询送给 CLIP，在图像库中检索匹配的图片。

![CuPL 流程](/images/lec16_cupl.webp)

CuPL 在 ImageNet 上提升了 0.65%，在 FGVC Aircraft（细粒度飞机分类）上提升了 3.81%，在 SUN397（场景分类）上提升了 3.43%。对于 CLIP 训练数据中覆盖较少的低频类别，LLM 生成的描述往往比人工写的模板更有信息量。

### VisProg：视觉编程

VisProg 把"链接模型"的想法推到了极致。核心理念：**不训练新模型，写程序。**

GPT 负责生成一个 Python 程序，程序里调用现成的视觉模块——OWL-ViT 做检测、CLIP 做分类、MaskFormer 做分割、Stable Diffusion 做编辑——然后把各模块的输出拼成最终的答案。

![VisProg 概念](/images/lec16_visprog.webp)

举例："船上有三个人吗？"VisProg 的流程是：

1. 用检测模型在图中找到"人"（返回每个人的位置和数量）
2. 用检测模型找到"船"（返回船的区域）
3. 判断哪些人位于船的区域内部
4. 统计数量，输出 Yes/No

整个过程不需要训练一个"多图 VQA 模型"——用现成的检测 + 空间推理模块组合就能完成。GPT 的角色是"编排者"，负责理解自然语言问题、拆解成子任务、决定调用哪个模块、写 glue code。

VisProg 的启示是：**组合已经很强的基础模型，很多时候比从零训一个端到端的新模型更实际**。每个模块在自己的领域内经过了充分优化和验证，组合起来的系统可解释性也更好——你能看到中间每一步的输出，而不是端到端模型给出的一个"魔法般"的答案。

## 小结

这节课的内容量很大，但有一条主线贯穿始终：**从专用模型到通用模型，从单模态到多模态，从训练到组合**。

| 模型/方法 | 视觉编码 | 文本/LLM | 对齐方式 | 输出 |
|-----------|---------|---------|---------|------|
| CLIP | ViT | Transformer | 对比损失 | 嵌入向量 |
| CoCa | ViT | Transformer + 解码器 | 对比 + 描述生成 | 嵌入 + 文本 |
| LLaVA | CLIP ViT | 微调 LLM | 线性投影 | 文本 |
| Flamingo | 冻结 ViT | 冻结 LLM | 逐层门控交叉注意力 | 文本 |
| Molmo | CLIP ViT | 微调 LLM | 简单 connector | 文本 + 坐标 |
| SAM | ViT | 无 | Prompt 编码器 | 分割掩码 |

几个贯穿全文的主题：

* **对比学习是连接视觉和语言的桥梁**，但它的全局相似度对组合性推理天然不友好
* **视觉 token 怎么喂给 LLM** 有不同的设计选择：LLaVA 的线性投影简单但有效，Flamingo 的门控交叉注意力更灵活但更复杂，Molmo 证明了简单的 connector 配合高质量数据就够用
* **数据质量胜过数据量**——Molmo 的 70 万精选对比 60 亿网页对，效果反而更好
* **模型不一定要更大**——把现有的强模型链接起来 (CuPL, VisProg) 是更务实的路线
* **分割也可以做成基础模型**——SAM 通过可提示接口和迭代数据引擎，把分割从"固定类别"变成了"任意类别"
